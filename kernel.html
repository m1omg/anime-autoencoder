🌀 Kernel Lab

Seven live demos of kernel methods — the branch of machine learning that solves problems by replacing the dot product, not by descending a gradient. Everything on this page is written from scratch in vanilla JS (SMO, Cholesky, orthogonal iteration, kernel PCA — no libraries), and every model here is fit in closed form or by convex optimisation: no epochs, no learning rate, no local minima.
The sister page on this repo trains a neural autoencoder for minutes to squeeze anime faces into two numbers. The last demo below does the same job with an eigenvector and a linear solve, in about a second. That contrast is the point of this page.  ← the autoencoder · source

① The kernel trick — a straight line in the right space

These two classes are a ring inside a ring: no straight line in 2D can separate them. But send every point through φ(x,y) = (x², √2·xy, y²) and the problem becomes trivially linear — a flat plane slices the two classes apart. Drag the slider to lift the data; drag the canvas to orbit.

🛸 φ-space (drag to orbit)
Lift into feature space

The catch: you never actually compute φ. Every algorithm on this page touches the data only through inner products, and

⟨φ(a), φ(b)⟩ = (a·b)² = k(a, b)

— the same number, at a fraction of the cost. That identity is the kernel trick. Hover the canvas to check it live, with a = your cursor and b = (0.6, −0.35):

The canvas draws φ-space in a rotated orthonormal basis — (x²−y²)/√2, √2xy, r²/√2 — because a rotation leaves every inner product (and so the kernel) exactly unchanged while standing the separating direction r² upright. The rings become a cone, and the plane that splits them is simply horizontal.

Why bother? For degree-d polynomials on n inputs, φ has C(n+d−1, d) coordinates. On a 64-pixel patch at degree 8 that is … dimensions — more numbers than atoms in a small object — and (a·b)⁸ computes their inner product in 64 multiplies and one pow. The RBF kernel below goes further: its feature space is infinite-dimensional, and it still costs one exp.

② Kernel SVM, solved by hand-written SMO

Click the canvas to add points (shift-click or right-click for the other class). The support vector machine is re-solved from scratch on every change with Sequential Minimal Optimisation — Platt's 1998 algorithm, ~120 lines below this page's HTML. It maximises a concave objective under one linear constraint, so it has one optimum and always finds it. Ringed points are the support vectors: the only points the model keeps.

③ Kernel ridge regression = a Gaussian process

Click to place observations (shift-click to remove the nearest). The curve is the exact posterior mean, the band is ±2σ, and the faint threads are functions sampled from the posterior. There is no fitting loop anywhere — one Cholesky factorisation gives the whole thing:

The log marginal likelihood is how a GP grades its own hyperparameters — no validation set needed. Try tuning ℓ to maximise it.

That is the honest meaning of "choosing a kernel" — it is choosing a prior. ④ Kernel PCA — unrolling a shape nobody could unroll linearly

Ordinary PCA can only rotate. Kernel PCA takes the eigenvectors of the centred kernel matrix instead of the covariance matrix, which is the same computation performed in φ-space — so it can bend. Watch what happens to concentric rings: linear PCA leaves them nested — hopeless for a linear classifier, because rotating a ring gives you another ring — while kernel PCA pulls them apart into two groups a single straight line can cut.

The spectrum panel shows why this works: linear PCA of a ring dataset has two nearly-equal eigenvalues and nowhere to go, while the kernel spectrum has a long informative tail — those extra components are directions in an infinite-dimensional space that simply do not exist in the input. Caveat worth knowing: kernel PCA gives you coordinates but no easy way back — recovering an input from a φ-space point is the pre-image problem, and it has no exact solution. Demo ⑦ works around it.

⑤ Random features — where kernels turn into neural networks

Kernels have one fatal flaw: the matrix is n × n. A million points means a trillion entries. Rahimi & Recht's fix (2007) inverts the trick — instead of avoiding the feature map, approximate it with a short random one. Bochner's theorem says any shift-invariant kernel is the Fourier transform of a probability measure, so sampling D frequencies from it gives:

z(x) = √(2/D)·cos(Wx + b),  W ~ 𝒩(0, 2γI),  b ~ U[0,2π]  ⟹  z(a)ᵀz(b) ≈ exp(−γ‖a−b‖²)

Now read that formula again as an engineer: cos(Wx + b) with random, never-trained W and b is a one-hidden-layer neural network. Fit a linear model on top and you have a kernel machine. This is the bridge between the two halves of machine learning — and it runs in both directions: an infinitely wide random network has an exactly computable kernel (the neural tangent kernel), which is how a chunk of modern deep-learning theory is done. The error falls like O(1/√D), the straight line you see in the error panel — Monte Carlo, not magic.

⑥ Attention is kernel smoothing wearing a hat

The operation at the heart of every transformer, softmax(QKᵀ/√d)·V, is a 1964 statistics result: the Nadaraya–Watson estimator, a weighted average of values whose weights are a kernel evaluated between query and keys. Below, the dots are (key, value) pairs and the curve is what attention returns for every query. Hover to see the attention weights for that query.

Effective keys is exp(entropy of the weights) — how many keys the query is really looking at. Slide τ from left to right and watch a model go from 1-nearest-neighbour lookup (τ→0, a staircase) to the global mean (τ→∞, a flat line), passing through smooth regression in between.

This reframing is not just cute — it is load-bearing. Linear-attention models (Performer, Linear Transformer) are exactly demo ⑤ applied here: replace the softmax kernel with random features z(q)ᵀz(k), and attention's cost drops from O(n²) to O(n) because you can now reassociate the matrix product. Every efficient-attention paper is, underneath, a kernel approximation paper.

⑦ 🌸 The same anime latent space — with no training at all

This is the punchline. The main page of this repo trains a neural autoencoder for minutes — Adam, backprop, learning-rate schedules, a bottleneck of 2 numbers — to build a latent map of eight anime faces. Here is that same map, built by kernel PCA: take the RBF kernel matrix of the images, centre it, grab the top 2 eigenvectors. No gradient steps. No epochs. One eigen-solve.

Decoding back to pixels is the pre-image problem from demo ④, so we sidestep it with a second closed-form model: kernel ridge regression from the 2D latent code to raw pixels, which is one Cholesky solve. Drag the cursor across the map — the decoder paints whatever lives at that point.

Support is the total kernel weight the cursor collects from the 128 stored samples. Where it falls to zero the decoder has nothing to go on and can only return the average face — so the map fades to black there instead of inventing detail. That dark region is the honest edge of what this model knows.

Read the trade honestly. The kernel version fits in a few hundred milliseconds and cannot get stuck — there is no optimiser to get stuck. But it is transductive and O(n²): it stores every image forever, the Gram matrix grows quadratically, and encoding a genuinely new face means comparing it to all of them. The autoencoder pays minutes up front and gets a compact, reusable function — a few megabytes of weights that encode any image in one forward pass and never look at the training set again. That, in one page, is why deep learning won at scale and why kernels never actually left: below roughly ten thousand samples, the closed form is usually the better engineer's choice.
